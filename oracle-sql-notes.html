Oracle & SQL Notes

A working reference covering database fundamentals, SQL command families, data types, functions, joins, views, indexing and normalization — organized the way the topics are usually taught, front to back.

01

Database, DBMS & RDBMS

Database

A database is an organized collection of data (information) — a collection of different database objects.

DBMS

A database management system is software used to manage a database. A user or application interacts with the DBMS to perform actions on the database. Plain DBMS applications store data as files — for example XML files or the Windows Registry.

RDBMS

A relational database management system is a database built on the relational model. RDBMS applications store data in tabular form, and almost every RDBMS uses SQL for querying.

A relational database stores data in a structured format of rows and columns. Values within a table relate to each other, and tables may relate to other tables — which makes it possible to query across multiple tables at once. Examples: Oracle, MySQL, Microsoft SQL Server.

04

DDL commands

1. Create

Used to create objects.

create table table_name (column1 datatype(size), column2 datatype(size)...);
-- example
create table emp (empno varchar2(10), ename varchar2(10), salary number(10));

2. Alter

Used to add, modify, rename, or drop a column.

a) Add

Adds a new column (or several at once).

alter table table_name add column_name datatype(size);
alter table table_name add (column_name datatype(size)); -- multiple columns
-- example
alter table emp add mgr varchar2(10);

b) Modify

Changes an existing column's data type or size (n columns at once).

alter table table_name modify column_name datatype(size);
-- example
alter table emp modify salary varchar2(10);

c) Drop

Removes columns from a table (n columns at once).

alter table table_name drop column column_name;
-- example
alter table emp drop column empname;

d) Rename

Renames one column at a time.

alter table table_name rename column old_name to new_name;
-- example
alter table emp rename column salary to sal;

3. Drop

Removes a database object entirely — both structure and data.

drop table emp;

4. Rename

Renames a table.

rename emp to employee;

5. Truncate

Deletes all data in a table but keeps the structure.

truncate table emp;

05

DML commands

1. Insert

Inserts data into the columns of a table. There are a few ways to do it.

Direct method

Values are provided directly against the table (all columns must be supplied):

insert into emp values ('alex', 2000, 20);

To insert values for specific columns only:

insert into emp (empname) values ('hanuma');

Reference method

Inserts multiple rows through interactive prompts:

insert into emp values (&eno, '&empname');

Oracle never makes DML changes permanent until they are committed. Character data must always be wrapped in single quotes.

2. Update

Updates existing rows based on a where condition.

update emp set sal = 2000 where empid = 123;

Use is — never = — to compare against null: update emp set sal = 2000 where empid is null;

3. Delete

delete from emp; -- clears table content
delete from emp where ename = 'alex'; -- deletes specific records

06

DRL — Select

Used to retrieve the desired data from a table. You can select specific columns or *, and apply filters such as where, group by and having.

select * from emp;
select ename, sal from emp;

07

TCL commands

Transaction control commands are used to validate transactions.

Commit

Makes DML changes permanent.

commit;

Rollback

Reverts changes made since the last commit point.

rollback;

Savepoint

Marks a point in the transaction to roll back to later.

insert into emp (empno, sal) values (01, 2000);
savepoint A;
insert into emp (empno, sal) values (02, 3000);
savepoint B;
insert into emp (empno, sal) values (03, 4000);
savepoint C;
-- can now: rollback to A / B / C, or commit to A / B / C

08

DCL commands

Data control statements enforce database security — granting defined roles and access privileges to users.

Grant

A DBA or user can grant access permissions to others.

grant [privilege] on [object] to {user | public | role};
-- when a user is newly created, a DBA typically grants:
grant create session to alex;
grant connect resource to alex;
-- to let a user select from a table:
grant select on emp to alex;

Privileges are permission names such as select, insert, update, delete, execute.

Revoke

Takes back an existing privilege. Only a DBA, or a user with the admin option, can revoke a system privilege.

revoke [privilege] on [object] from {user | public | role};
-- example
revoke select on emp from alex;

09

The dual table

dual is a dummy table with a single column (dummy, type varchar2(1)) and exactly one row holding the value X. It's the standard table for evaluating expressions or calling functions without needing a real table.

10

Operators in SQL

1. Arithmetic operators (+, -, *, /)

select sal/2 from emp;
select 300+400 from dual;

2. Logical operators (and, or, not)

select * from emp where deptno = 10 and sal > 1000;
select * from emp where deptno = 10 or sal > 1000;
select * from emp where deptno != 10;

3. Relational operators

= equal to
< less than
> greater than
<= less than / equal
>= greater than / equal
!= / <> not equal
select * from emp where salary <> 2000;

4. Special operators

IS — behaves like =, used to handle null values. Nulls must always be compared with is.

select * from emp where comm is null;
select * from emp where comm is not null;

IN / NOT IN — compares against a list of values (character, number or date):

select * from emp where sal in (1000, 2000, 10000);
select * from emp where manager in ('ram', 'martin');
select * from emp where sal not in (4000, 5000);

BETWEEN / NOT BETWEEN — a range of values:

select * from emp where sal between 1000 and 3000;
select * from emp where sal not between 4000 and 6000;

LIKE / NOT LIKE — pattern search. % is a wildcard for any run of characters, _ matches a single character.

select * from emp where ename like 'ra%';
select * from emp where ename like 'p____';
select * from emp where ename like '%p%';

ANY / SOME — compares a value against every value in a list; must be paired with =, !=, >, <, >=, <=.

select * from emp where sal >= all (1400, 3000);

11

Set operators

Set operators combine the results of select statements — sometimes called "virtual joins." The one precondition is that the corresponding columns share the same data type.

  • Union — combines results and eliminates duplicate rows.
  • Union all — combines results, duplicates kept.
  • Intersect — returns rows common to both queries.
  • Minus — returns rows present in the first query but not the second.
select empno from emp union select mgr from emp;
select empno from emp union all select mgr from emp;
select empno from emp intersect select mgr from emp;
select empno from emp minus select mgr from emp;

13

String functions

Length

select length('Alexander') from dual; -- 9

Reverse, Upper, Lower, Initcap

reverse reverses a string; upper/lower change case; initcap capitalizes the first letter and lowercases the rest.

Concat / ||

concat joins exactly two strings. To join more than two, use the pipe operator ||.

select concat('greg', 'martin') from dual; -- gregmartin
select 'EBS' || 'solutions' || 'for' || 'technical' from dual;

Substr(expression, m, n)

Returns characters from a string starting at position m for n characters. If m is 0 it's treated as 1; positive m counts from the start; negative m counts backward from the end; omitting n returns everything from m to the end; n < 1 returns null.

select substr('technologies', 2, 4) from dual; -- echn
select substr('technologies', 2) from dual; -- echnologies
select substr('technologies', -2) from dual; -- es

Instr

Returns the numeric position of a substring, searching from the m'th character for the n'th occurrence. Negative m searches backward. Default m and n are both 1. Returns 0 if not found.

select instr('orporatororders', 'or') from dual; -- 2
select instr('orporatororders', 'or', 4) from dual; -- 5
select instr('orporatororders', 'or', -1) from dual; -- 17 (search backward)
select instr('orporatororders', 'or', 1, 2) from dual; -- 5 (2nd occurrence)

Trim / Ltrim / Rtrim

trim removes leading, trailing, or both instances of a character; if unspecified, both sides are trimmed.

trim('0' from '002200'); -- 22
trim(leading '0' from '002200'); -- 2200
trim(trailing '0' from '002200'); -- 0022

ltrim / rtrim strip specified characters from the left / right of a string — every character in the given set is stripped, not just a literal match.

ltrim('6372tech1234', '0123456789'); -- tech1234
rtrim('6372tech1234', '0123456789'); -- 6372tech

Lpad / Rpad

Pad a string on the left or right up to a given length, using a specified character (space by default).

lpad('tech', 8, '0'); -- 0000tech
rpad('tech', 8, '0'); -- tech0000

Translate

Character-by-character replacement in a string.

translate('1tech23', '123', '456'); -- 4tech56

Replace

Replaces (or removes, if no replacement is given) a sequence of characters.

replace('123tech324', '123', '456'); -- 456tech324
replace('123123tech', '123'); -- tech (removed)

14

Date functions

Sysdate

Returns the system date and time; you can add or subtract from it.

select sysdate from dual;
select sysdate - 1 from dual;

Current_date

Returns the current date in the time zone of the current SQL session (set via alter session).

Add_months

select add_months(sysdate, 3) from dual;
select add_months(sysdate, -3) from dual;

Months_between

select months_between(sysdate, '15-sep-19') from dual;

Next_day / Last_day

select next_day(sysdate, 'monday') from dual;
select last_day(sysdate) from dual;

Conversion functions

To_char

Converts a number or date into a string.

With numbers

to_char(1210.73, '9999.9'); -- 1210.7
to_char(1210.73, '9999.99'); -- 1210.73
to_char(21, '000099'); -- 000021

With dates

to_char(sysdate, 'yyyy/mm/dd'); -- 2010/03/10
to_char(sysdate, 'month dd,yyyy'); -- July 09,2003
to_char(sysdate, 'fmmonth,yyyy'); -- july9,2003

Converts another date format into Oracle's default format.

To_number

16

General functions

User / Uid

select user from dual;
select uid from dual;

Nvl / Nvl2

nvl(col, replacement) substitutes a value for a null. nvl2(col, value_if_not_null, value_if_null) extends it to handle both cases.

select nvl(sal, 10000) from emp;
select nvl2(sal, 10000, 20000) from emp;

Nullif(expr1, expr2)

Returns null if the two expressions are equal, otherwise returns expr1.

nullif(10,10); -- null
nullif(20,10); -- 20

Coalesce(expr1, expr2, ... exprn)

Returns the first non-null expression in the list; null if every expression is null.

Case

Implements if-then-else logic. Two forms: simple and searched.

Simple case expression — compares one expression against each option:

select cust_last_name,
  case credit_limit
    when 1000 then 'low'
    when 5000 then 'high'
    else 'medium'
  end
from emp;

Searched case expression — evaluates independent conditions per branch:

select case
  when empno in (1234,1235) and sal > 5000 then 'first grade'
  when empno in (1236,1237) and sal < 5000 then 'second grade'
  else 'third grade'
end;

Simple case checks equality against each option; searched case can combine multiple conditions with and. Maximum 255 options in a case expression; omitting else returns null.

Decode

If-then-else style substitution.

decode(col_name, value, result, value, result, ..., default_value);
-- example
select decode(s_area, 'bellandur','karnataka', 'rct','a.p', 'chennai','t.n', 'rest of india') from table_name;

Decode vs case — case supports all logical operators (=, <>, >, < ...); decode only supports equality checks. Case can use subqueries; decode cannot. Case expects data-type consistency across branches; decode does not.

17

Aggregate functions

Aggregate functions return a single result per group of rows, and can only appear in the select list and having clauses.

FunctionReturns
avg(col)Average value (ignores nulls)
sum(col)Total value
max(col) / min(col)Maximum / minimum value
stddev(col)Standard deviation
variance(col)Variance
count(*) / count(col)Row count including nulls / distinct non-null count
distinct(col)Eliminates duplicate rows
greatest(col1...coln)Greatest value per row across the listed columns
least(col1...coln)Least value per row across the listed columns

For example, given per-subject marks for several students, greatest(s1,s2,s3,s4,s5,s6) returns each student's highest subject score, row by row — unlike max, which would collapse the whole column.

18

Clauses

1. Where

Limits records by condition. A where clause does not allow group functions.

select * from emp where sal > 1000;
select * from emp where deptno = 20 and hiredate > '01-JUN-81';

2. Group by

Groups rows that share values in one or more columns — typically used together with an aggregate function in the select list.

select deptno, sum(sal) from emp where sal > 500 group by deptno;

Every non-aggregated column in the select list must appear in the group by clause. A where clause, if present, precedes the group by clause.

3. Having

Filters the rows returned by a group by clause. Cannot be used without one.

select deptno, max(sal) from emp where sal > 2000 group by deptno having max(sal) > 3000;

4. Order by

Sorts rows, ascending by default.

select ename, sal from emp where sal > 2000 order by empno, sal;
select empno, sal, mgr from emp order by sal desc;

Instead of column names, you can order by their position in the select list: order by 2 sorts by the 2nd selected column.

19

Analytical functions

Analytical functions help analyze data across groups of rows.

Rollup

Calculates multiple levels of subtotals across the specified dimensions, plus a grand total — an extension of group by.

select job, count(*) from emp group by rollup(job);
select deptno, job, count(*) from emp group by rollup(job, deptno);

Cube

Calculates subtotals for every possible combination of the grouped dimensions.

select deptno, job, count(*) from emp group by cube(job, deptno);

Rank

Returns the rank of a value within a group of values. Ties get the same rank, and ranks after a tie are skipped (non-consecutive). Usable as an aggregate function or as an analytical function.

-- as aggregate function
select rank(1000) within group (order by sal) from emp;
-- as analytical function
select ename, rank() over (order by sal desc) from emp;
-- with partition by
select empno, ename, deptno, sal, rank() over (partition by deptno order by sal desc) from emp;

Dense_rank

Assigns ranks the same way, but without skipping ranks after ties — consecutive ranking.

select ename, dense_rank() over (order by sal desc) from emp;

20

Pseudo columns

A pseudo column behaves like a table column but isn't actually stored in the table — you can select from it, but never insert, update, or delete its values.

Rownum

Returns a number indicating the order Oracle selected each row, starting at 1. Can only be used meaningfully with <, <=, or = 1.

select * from emp where rownum < 5;
select * from emp where rownum = 1;

Rowid

The unique physical address of a row.

select rowid from emp;

Sequence pseudo columns — currval & nextval

currval returns the current value of a sequence; nextval increments the sequence and returns the next value.

21

Aliases

An alias is a temporary name for a table or column.

Column aliases

as defines an alternate name for a column heading (a space also works):

select sal as salary from emp;
select ename, sal, dense_rank() over (order by sal desc) rn from emp;

Table aliases

Used when the same table needs to appear more than once in a query — common with joins:

select a.ename, a.deptno, b.dname from emp a, dept b where a.deptno = b.deptno;

22

Constraints

Constraints are rules enforced on table columns, limiting what data can enter — ensuring accuracy and reliability. They can be defined at column level or table level.

1. Not null

Prevents null values (duplicates are still allowed).

create table student (s_name varchar2(10) not null, stu_id number(5), grade varchar2(5));
-- add to an existing table
alter table student modify stu_id number(5) not null;

A not-null constraint cannot be created at table level.

2. Unique

Prevents duplicate values, but allows any number of nulls (since two nulls are never considered equal).

-- column level
create table emp (ename varchar2(10), deptno number(15) constraint con_un1 unique, sal number(5) constraint con_un2 unique);
-- table level
create table emp (ename varchar2(10), deptno number(5), sal number(5), unique (deptno, sal));
-- add to an existing table
alter table student add constraint cons_uu1 unique (ename);

3. Check

Restricts the range of values that can be inserted into a column.

create table emp (ename varchar2(10), deptno number(5), sal number(6) check(sal between 1200 and 2200));

A check constraint still allows nulls — null is treated as a unique value. Pair it with not null if nulls should also be rejected.

4. Default

Supplies a default value when insert doesn't specify one (only applies with the direct insert method).

create table emp (stu_id number(9), sal number(9) default(90));
insert into emp (stu_id) values (1234); -- sal becomes 90

5. Primary key

Combines unique and not null. A table can have only one primary key, though a table-level primary key can span multiple columns.

-- column level
create table emp (ename varchar2(10), sal number(10), empid varchar2(10) constraint con_pk primary key, deptno number(10));
-- table level (composite key)
create table emp (ename varchar2(10), sal number(10), empid varchar2(10), deptno number(10), constraint con_pk1 primary key (ename, empid));

Defining a primary key or unique constraint automatically creates a unique index on those columns.

6. Foreign key (referential integrity)

Prevents actions that would break links between two tables — it points to the primary key (or a unique-constrained column) in another table. The referenced table is the parent table; the table holding the foreign key is the child table. The parent's referenced column must carry a primary key or unique constraint.

create table student (ename varchar2(10), deptno number(10) references emp(deptno));
-- or
create table student (ename varchar2(10), deptno number(10), foreign key(deptno) references emp(deptno));

Two delete-behavior options:

  • On delete cascade — deleting the parent row also deletes matching child rows.
  • On delete set null — deleting the parent row sets the matching child column to null.
create table student (ename varchar2(10) not null, stuno number(10), sal number(10) not null,
  constraint con_fk foreign key(deptno) references emp(deptno) on delete cascade);

Managing constraints

alter table table_name drop constraint constraint_name;
alter table table_name disable constraint constraint_name;
alter table table_name enable constraint constraint_name;

23

Sub queries

A query within a query. Sub queries can sit in a where clause (a "nested sub query"), a from clause (an "inline view"), or a select clause. Oracle allows up to 255 nested sub query levels in a where clause — there's no limit on inline views. They're most useful when selecting rows based on a condition drawn from the table's own data.

Single row sub query

Returns exactly one row; usable with =, <, <=, >, >=, <>, !=.

select * from emp where sal = (select max(sal) from emp);

Multiple row sub query

Returns one or more rows — needs in, not in, any or all in the outer query.

select ename, dept_id from emp where dept_id in (select dept_id from dept where location_id = 100);

Correlated sub query

References a value from the outer query, and may be evaluated once per outer row — so it tends to be slower.

-- employees earning above their department's average
select empno, ename, deptno, sal from emp a
where sal > (select avg(sal) from emp b where b.deptno = a.deptno);

24

Important queries

Duplicate records — display / delete

-- display duplicates
select * from table_name where rowid not in
  (select max(rowid) from table_name group by col1, col2, col3, col4);
-- delete duplicates
delete from emp where rowid not in
  (select max(rowid) from table_name group by col1, col2, col3, col4);
-- rows with count, showing how many times duplicated
select empno, ename, sal, deptno, count(*) from emp1
group by empno, ename, sal, deptno having count(*) > 1;

Nth highest salary

-- first highest
select max(sal) from table_name;
-- second highest
select max(sal) from table_name where sal not in (select max(sal) from table_name);
-- nth highest, general form
select * from (select table_name.*, dense_rank() over (order by sal desc) rn from table_name) where rn = n;
-- top 5
select * from (select table_name.*, dense_rank() over (order by sal desc) rn from table_name) where rn <= 5;

Even / odd rows

-- even
select * from (select rownum rn, emp.* from emp) where mod(rn,2) = 0;
-- odd
select * from (select rownum rn, emp.* from emp) where mod(rn,2) <> 0;

Other common patterns

-- above average salary
select * from emp where sal >= (select avg(sal) from emp);
-- highest-paid employee per department
select * from (select emp.*, dense_rank() over (partition by deptno order by sal desc) rn from emp) where rn = 1;
-- first / last record
select * from emp where rowid in (select min(rowid) from emp);
select * from emp where rowid in (select max(rowid) from emp);
-- rows 6 through 10
select * from emp where rownum <= 10
minus select * from emp where rownum <= 5;
-- count occurrences of a letter in a string
select length('good morning') - length(replace('good morning','o')) from dual;

Backups & copying tables

-- copy all columns and data
create table new_table as select * from old_table;
-- copy specific columns
create table new_table as select column1, column2 from old_table;
-- copy structure only, no data
create table new_table as select * from old_table where 1=2;
-- insert via select
insert into table2 select * from table1 where condition;

Source and target column data types must match when inserting via select.

25

Joins

Joins fetch data from more than one table or view. The columns being compared must share a similar data type. In the select list, columns should be uniquely identified — table.column or alias.column. For three or more tables, Oracle joins two tables first, then joins the result to the next table.

Oracle's join types: self join, inner join, outer join (left, right, full), and Cartesian / cross join.

1. Self join

Joins a table to itself — one row is matched against another row in the same table, using aliases to treat it as two tables.

-- finding an employee's manager name
select a.ename as "employee_name", b.ename as "manager_name"
from emp a, emp b where a.mgr = b.empno;
-- ANSI join syntax
select a.ename as "employee_name", b.ename as "manager_name"
from emp a inner join emp b on a.mgr = b.empno;

2. Inner join

Returns only rows that satisfy the join condition.

select a.ename, a.deptno, b.dname from emp a inner join dept b on a.deptno = b.deptno;
-- equivalent old syntax
select a.ename, a.deptno, b.dname from emp a, dept b where a.deptno = b.deptno;

3. Outer join

Returns matched rows plus all rows from one side, with nulls filling in unmatched columns from the other side.

Left outer join

All rows from the left table; matched data from the right table; unmatched right-side data becomes null.

select a.empno, a.ename, a.sal, b.deptno, b.dname, b.loc
from emp a left outer join dept b on a.deptno = b.deptno;
-- old syntax
... from emp a, dept b where a.deptno = b.deptno (+);

Right outer join

All rows from the right table; matched data from the left; unmatched left-side data becomes null.

select a.empno, a.ename, a.sal, b.deptno, b.dname, b.loc
from emp a right outer join dept b on a.deptno = b.deptno;

Full outer join

All rows from both tables; unmatched rows on either side become null. If table A has 6 rows, table B has 5, and 3 rows are common, the full outer join returns 6 + 5 − 3 = 8 rows.

select a.empno, a.ename, a.sal, b.deptno, b.dname, b.loc
from emp a full outer join dept b on a.deptno = b.deptno;

4. Cartesian / cross join

A join with no join condition — every row of one table is paired with every row of the other. Table A with 3 rows and table B with 5 rows produces 15 rows.

select a.*, b.* from emp a, dept b;

Views

A view is a logical representation of a table, based on one or more tables or views. It holds no data of its own — every select or DML operation hits the underlying base table. The tables a view derives from are its base tables (which can themselves be normal tables or other views).

Advantages

  • Restricts access — users can query a view for information without touching the base table.
  • Provides a layer of security over the table.
  • Simplifies complicated underlying queries for the end user.
  • Lets different groups of users see different shapes of the same data.

Types

Simple view — built on one table, no group functions. Supports DML directly.

Complex view — derives from multiple tables or includes group functions. DML isn't directly supported, but can be enabled through instead of triggers.

Materialized view — used to speed up select queries, especially with aggregation or joins across two tables. Unlike ordinary views, it occupies storage and must be refreshed after the base table changes.

DBMS_MVIEW.REFRESH(view_name); -- refresh a single materialized view
DBMS_MVIEW.REFRESH_ALL_MVIEWS; -- refresh all

Creating a view

create or replace [force|noforce] view view_name as select ... from table_name
[with check option | with read only];
  • force — creates the view even if the base table doesn't yet exist; it becomes usable once the table is created.
  • noforce (default) — refuses to create the view if the base table is missing.
  • with check option — rows retrieved by the view's where clause are the only ones that can be selected, inserted, updated, or deleted.
  • with read only — the view is read-only; no DML is allowed.

When a view is updatable

A view can be updated when it includes the base table's primary key, has no aggregate functions, no distinct, no group by/having, and no sub-queries in its definition. A view cannot be updated if it's built on nested or complex queries, lacks a key-preserved table, or contains pseudo columns or expressions.

Indexes

An index is an indicator that gives quick access to rows in a table, with an entry created for each value in the indexed columns. Oracle automatically creates a unique index for primary key and unique key constraints.

Advantages / disadvantages

Advantages: faster row retrieval, faster statement execution.

Disadvantages: extra disk space; slower insert/update/delete (the index has to be updated too); too many indexes can actually slow the database down.

Creating and dropping

create index index_name on table_name(columns); -- multiple columns = composite index
alter index index_name rebuild compute statistics;
drop index index_name;

If no index type is specified, Oracle creates a B-tree index by default. The all_indexes table holds metadata on every index.

Types

B-tree index — Oracle's default; branches lead down to leaf nodes that hold the data.

Bitmap index — stores a bitmap per index key, each pointing to multiple rows. Best for low-cardinality columns.

Unique / non-unique — unique indexes guarantee no two rows share a value in the key column(s); automatically created for unique/primary key constraints.

Clustered / non-clustered — a cluster groups tables sharing the same data block, useful when two tables are frequently joined (e.g. emp and dept joined via deptno).

Sequences

A sequence is an object that generates an auto-incrementing number, useful for guaranteeing a unique value per row.

create sequence sequence_name
start with value
increment by increment_value
minvalue minimum_value
maxvalue maximum_value
[cycle|nocycle]
[cache|nocache];

Defaults: start with 1, increment by 1, minvalue 1, cache 20, nocycle. Maxvalue defaults to an effectively infinite ceiling.

create sequence seq1 start with 10 minvalue 10 maxvalue 200 increment by 5 cycle;
-- decrementing sequence
create sequence seq1 start with 200 minvalue 0 maxvalue 200 increment by -10 cycle;
-- alter
alter sequence seq1 increment by 20 maxvalue 200;
-- drop
drop sequence sequence_name;

With cycle, the number of values the sequence can generate must be at least the cache size, or Oracle raises ORA-04013. Pair cycle with nocache to sidestep that restriction.

29

Synonyms

A synonym is an alternate name for an object — a table, view, sequence, procedure, and so on — useful for giving a short name to something long or complicated.

create or replace [public] synonym synonym_name for object_name;
-- example
create synonym syn_emp for emp;

A public synonym is accessible to every user in the database and owned by the group PUBLIC. A private synonym lives in one schema and is available only to its owner.

Normalization

Normalization is the technique of organizing data in a database — creating tables and relationships according to rules designed to protect the data and keep the database flexible. It works by eliminating redundancy and inconsistent dependency. There are four normal forms in common use: 1NF, 2NF, 3NF, and BCNF.

First normal form (1NF)

Every table cell must contain a single value, and every record must be unique.

Before 1NF
NameAgeSubject
Martin15biology, maths
Alex14maths
After 1NF — one value per cell, each row unique
NameAgeSubject
Martin15biology
Martin15maths
Alex14maths

Second normal form (2NF)

No column may have a partial dependency on the primary key — every non-key column must depend on the entire composite key, not just part of it. In the 1NF example, age depends only on name, not on the composite (name, subject) key — a 2NF violation. Splitting subject into its own table, linked back by name, resolves it.

Student
NameAge
Martin15
Alex14
Subject
NameSubject
Martinbiology
Martinmaths
Alexmaths

Third normal form (3NF)

Every non-key column must depend directly on the primary key — not on another non-key column. That kind of indirect dependency is a transitive dependency, and it must be removed (in addition to satisfying 2NF).

Example: in a student-detail table keyed on student_id, if street, city and state all really depend on zip rather than directly on student_id, that's a transitive dependency. The fix is to move zip and its dependents into their own table, keyed on zip — reducing duplication and improving data integrity.

Boyce-Codd normal form (BCNF)

A stronger version of 3NF, sometimes called 3.5NF. Even a table already in 3NF can still show anomalies if it has more than one candidate key — BCNF addresses the cases 3NF doesn't catch.
